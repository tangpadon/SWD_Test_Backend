## Response Section
### ข้อดี
- เพิ่มความเร็วในการอ่านข้อมูล ช่วยลดเวลาประมวลผลคำสั่ง SELECT ที่มีเงื่อนไข WHERE หรือการค้นหาช่วงข้อมูล
- คอลัมน์ที่ถูกทำ Index จะมีการเรียงลำดับค่าไว้ล่วงหน้า ทำให้คำสั่ง ORDER BY หรือ GROUP BY ดึงผลลัพธ์ได้ทันทีโดยไม่ต้องเสียแรง CPU ไปคำนวณ Sort ซ้ำ
- ฐานข้อมูลอ่านเฉพาะ Node ของ Index และบล็อกข้อมูลที่ตรงเงื่อนไขเท่านั้น ลดการอ่านข้อมูลปริมาณมหาศาลจาก Disk เข้าสู่หน่วยความจำ
- ใช้สร้าง Unique Index เพื่อบังคับไม่ให้ข้อมูลในคอลัมน์ซ้ำกัน เช่น เลขบัตรประชาชน หรืออีเมล
- ในการ JOIN ตาราง จะช่วยให้ฐานข้อมูลจับคู่ Foreign Key ระหว่างตารางได้อย่างรวดเร็ว ลดภาระการสแกนตารางขนาดใหญ่
### ข้อเสีย
- ประสิทธิภาพการเขียนลดลง เมื่อมีการรันคำสั่ง INSERT, UPDATE หรือ DELETE ฐานข้อมูลต้องเสียเวลาอัปเดตและจัดเรียงโครงสร้าง Index ใหม่ทุกครั้ง ยิ่งสร้าง Index ไว้หลายตัว การเขียนข้อมูลก็จะยิ่งช้าลง
- Index ใช้พื้นที่บนดิสก์และแรมเพิ่มเติม ในกรณีที่ตารางมีหลาย Index ขนาดของไฟล์ Index รวมกันอาจใหญ่กว่าขนาดข้อมูลจริงของตาราง
- ไม่ได้ช่วยให้เร็วขึ้นสำหรับข้อมูลที่มีความหลากหลายต่ำ การทำ Index กับคอลัมน์ที่มีค่าซ้ำกันมาก ๆ เช่น เพศ ชาย/หญิง หรือสถานะเปิด/ปิด จะไม่ช่วยให้เร็วขึ้น
- เมื่อใช้งานไปนาน ๆ โครงสร้างต้นไม้ของ Index อาจเกิดการกระจัดกระจายซึ่งจำเป็นต้องมีการ Rebuild เพื่อคืนประสิทธิภาพ

การทำ Indexing เหมาะกับตารางที่มีสัดส่วนการ "อ่านบ่อยกว่าเขียน" (Read-heavy) และควรเลือกทำเฉพาะคอลัมน์ที่ถูกนำไปใช้ใน WHERE, JOIN หรือ ORDER BY เป็นประจำเท่านั้น
